# SideMind 真实模型评测

后续多步效率优化已完成冻结版本的真实模型对照：两个任务各前后两次，总调用 39 → 26，纯计划/导航往返 11 → 0；独立纠正与恢复回归 36 项检查通过。逐次耗时（含一个新版更慢的样本）、人工核验、完整测试中的 watcher 间歇失败及限制见[多步任务效率对照](efficiency-2026-10-15.md)。下方保留此前发现问题与修复的历史记录。

这些场景通过当前已配置的真实模型运行生产 `NoteAgent`、`AgentRunService` 和文件工具。脚本仅负责建立合成笔记、提交自然语言任务、在指定边界注入故障、保存轨迹和核对文件；不替换模型回复，也不预设模型的工具调用顺序。最终产物、证据使用、澄清是否必要和回复真实性还需按各场景的 `humanReview` 人工检查。

## 运行

在项目根目录，使用支持项目依赖的 Node.js 运行。需要先在 SideMind 配好模型。执行会调用该模型并消耗对应账户额度；普通 `npm test` 不会触发。

```sh
npm run eval:live -- smoke
npm run eval:live -- multistep cross-note-research-brief
npm run eval:live -- multistep exhibition-decision-and-canvas
npm run eval:live -- corrections
npm run eval:live -- recovery recovery-concurrent-edit
npm run eval:live -- recovery recovery-committed-write-receipt-lost
npm run eval:live -- recovery recovery-concurrent-decision-changed
```

若真实调用在部分工具已完成后失败，可以显式恢复原临时笔记库和会话：

```sh
SIDEMIND_EVAL_OUTPUT=/tmp/sidemind-live-resumed npm run eval:live -- multistep cross-note-research-brief --resume /tmp/sidemind-live-efficient/cross-note-research-brief.json
```

恢复会发送“先核对已保存内容，不要重复新建或移动，完成剩余核验”的自然语言续接，不自动重放旧工具。它只接受对应场景的系统临时目录，跳过初始化和故障注入，保留此前轨迹、原实现哈希及恢复边界；输出不能覆盖源报告。这里的 `--resume` 是评测入口，不是新的产品自动重试策略。

省略场景 ID 会运行该模块全部场景；`recovery` 还包含临时读取失败场景，2026-10-15 这轮尚未实际运行它。

- 每次运行在系统临时目录建立全新的合成笔记库，移除仅属于新库的自动 Welcome 笔记，不读写现有笔记正文。
- 默认依据项目的 `workspace` 读取现有模型连接设置，沿用生产模型选择顺序，不修改模型选择。`SIDEMIND_EVAL_SOURCE_WORKSPACE` 可指定连接设置对应的工作区路径；认证由原有连接管理，必要时正常刷新令牌，不复制认证文件。
- `SIDEMIND_EVAL_OUTPUT` 指定报告目录，默认 `/tmp/sidemind-live-eval`。不同复测应使用不同目录，避免覆盖同名场景基线。
- JSON 报告包含合成笔记最终快照、用户指令、工具轨迹、终态、逐项检查、耗时和模型标签。新报告还记录关键服务文件 SHA-256；不记录请求头、令牌或加密推理项。
- 每轮用户任务默认最多 30 次模型调用。校验失败、无校验项或执行异常返回非零退出码；正常终态本身不代表用户任务完成。
- 评测库未配置 Git 历史和语义索引。测试没有覆盖同步、真实账号外部操作、浏览器界面全链路、多模型横向比较或长周期稳定性。

## 2026-10-15 实际结果

本轮使用现有连接 **ChatGPT · gpt-6.1-sol**。表中调用数包含工具调用后的继续推理；耗时是本次观测值，不能当作性能保证。每个任务都检查了真实工具轨迹及落盘内容。

| 任务 | 调用 / 耗时 | 人工与文件检查结果 |
| --- | --- | --- |
| 搜索并阅读指定信息 | 3 / 19.3 秒 | 修复流式解析后，搜索→读取→回答正确，笔记不变 |
| 跨笔记研究简报、迁移来源、修复链接 | 12 / 117.3 秒 | 正确区分意向与事实，保留原文，双向链接有效，只有一篇简报 |
| 策展决策并整理画布 | 12 / 144.4 秒 | 预算和容量正确，不扩大访谈/授权结论；新增两组，旧档案组位置、尺寸、成员和原文保留 |
| 首次写入后中止，再连续纠正时间和地点 | 19 / 140.3 秒，含 3 轮用户任务 | 同一会话继续，三篇信息一致；保留负责人、约束和检查项，没有重复汇总或写入长期偏好 |
| 并发追加无关内容：修复前 | 8 / 55.3 秒 | **任务失败**：虽正常终止，仍重复索取授权，两篇目标日期未改 |
| 并发追加无关内容：修复后 | 11 / 74.9 秒 | 重读最新版本，保留新追加内容，完成两篇日期修改并核验 |
| 写入已成功，但成功回执丢失 | 10 / 68.1 秒 | 查询并读回已存在的结果，只创建一次，来源不变 |
| 并发修改直接改变目标并增加冻结约束 | 5 / 27.9 秒 | 保留新日期和冻结要求，提出相关澄清，没有覆盖新决定 |
| 真实模型超时后的同会话恢复 | 失败尝试 8 / 99.8 秒；恢复 4 / 36.0 秒 | 原库原会话继续，只读取并核验；全部六篇笔记与超时后快照相同，没有重复创建、移动或编辑，7 项检查通过 |

### 从真实失败得到的修改

1. 真实 Responses 流在 `response.output_item.done` 提供完整工具项，但终态 `output` 为空。旧解析器因此报“未返回有效修改内容”。现在保存完成的输出项，仅在收到成功终态后采用；中断或不完整响应仍不能执行工具。补充了协议回归用例，并用真实搜索/阅读和后续任务验证。
2. 原冲突指令一律要求询问，导致已授权任务遇到无关追加也停止。现在先重读、比较；能保留新增内容且目标不变就继续，目标或约束发生实质变化才澄清。上述两个相反边界都实际运行过。
3. 真实取消与后续纠正可以依靠会话记录继续，但旧界面在生成期间不能直接发送调整。Arc AI Chat 现在提供“停止并发送调整”，等待旧任务持久化终态后继续同一会话；停止失败保留草稿，Esc 可以取消待发送调整。界面并发和生命周期由专门回归测试覆盖，不将这些模拟 UI 测试计为真实模型测试。
4. 完整回归发现普通对话 `RunService` 也会在终态落盘前发布完成状态，导致轮询客户端过早进入后续流程。现已先等待进度写入、保存终态，再发布完成；用阻塞最终文件发布的确定性测试验证查询和 SSE 均不会提前完成。不是靠增加等待时间消除测试失败。

### 验收记录与限制

研究简报基线有一项自动检查误报：初始化自动生成的 Welcome.md 被计入“额外笔记”。保留原始失败报告，另存修订检查和人工评审；没有修改模型轨迹。此后 harness 在建立合成库时移除 Welcome。冻结边界用例也修正了这一夹具计数并保留 `originalChecks` 和 `verificationRevision`。这两项不是模型失败。

原始报告保留在本机 `/tmp/sidemind-live-fixed-transport/`、`/tmp/sidemind-live-baseline/`、`/tmp/sidemind-live-baseline-corrections-v2/`、`/tmp/sidemind-live-baseline-recovery/` 和 `/tmp/sidemind-live-recovery-fixed/`。它们是本地诊断产物，未提交仓库；系统清理临时目录后可能不再存在。

回归测试最终为 419 项通过、9 项跳过，类型检查及生产构建通过；jsdom 的既有 `scrollTo` 提示和构建大包提示仍在。初次完整运行出现的 `branches` 清理竞态已定位并按上述持久化顺序修复。

这些是少量明确场景的实际观察，能定位集成缺陷和恢复边界，不能据此宣称任意任务均能泛化。多步基线存在过多单独计划/导航往返和正文偏长的问题。调整通用编排与篇幅指令后的复测已生成语义正确的简报，但第 8 次模型调用超时，未完成最后核验；失败报告保留在 `/tmp/sidemind-live-efficient/`。正文从 2062 变为 1724 个 Unicode 字符（含 Markdown），但未完成轨迹不能用于证明调用次数或耗时改善。随后显式恢复，完成剩余核验且没有重复副作用，报告和人工评审位于 `/tmp/sidemind-live-efficient-resumed/`。恢复仍有两轮单独计划更新，因此没有将减少往返列为已验证收益。
