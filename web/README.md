# Sidemind（Web 版）

> **Sidemind = side + mind，“在你旁边的另一颗头脑”。** 正在读或写的时候，随时在旁边岔出一条线去研究；想清楚了，再有选择地收回到正文里。
> 本应用原名 Canvas Note，与 ChatGit 合并后改为此名。命名原因、含义与改名范围见根目录 `统一工作台-产品计划-v1.md` 第 0 节。

一个在浏览器里使用的 Markdown 笔记应用：**画布上的一张卡片是一篇完整文章，不是文章中的段落。**
每个真实文件夹对应一个画布；文章正文是普通 `.md` 文件，位置独立保存。
设计依据见仓库根目录的 `技术路线-v0.2-Web.md`。

## 运行

```sh
npm install
npm run dev        # 同时启动笔记服务（3001）和网页（5173）
```

打开 http://localhost:5173 。

- 数据目录默认是 `web/workspace`，可用环境变量 `SIDEMIND_DATA_DIR=/你的/数据目录` 指定（旧名称 `CANVAS_DATA_DIR`、`NOTES_DIR` 仍可用）。数据目录是一个 Git 仓库：`notes/` 是 Markdown 笔记，`memory/` 是助手的记忆，`canvas/` 是每个文件夹的画布布局，`cache/` 是不提交的本机缓存。设计见根目录 `技术路线-v0.3-AI-Agent.md`。
- 统一工作台开发分支使用数据格式 v2：`research/` 保存笔记的稳定身份；`local/` 保存不可随意删除的对话、提案、撤销和恢复记录。`local/` 不进 Git，但必须包含在完整数据备份里。旧 `cache/` 中的这三类历史首次打开时复制到 `local/`，保留旧副本，不反复覆盖新记录。请只用测试副本试用本分支，不让旧程序再次打开升级后的目录。
- 数据目录的版本标记是 `sidemind.json`。旧版 Canvas Note 的 v1/v2 目录首次启动时原地升级（加上新标记；旧文件名 `canvasnote.json` 保留为版本 99 的“拒绝标记”，防止旧版 Canvas Note 误打开并改动新数据）。旧版 v0.2 工作区（Markdown 直接放在根目录、带 `.canvasnote/`）同样在首次启动时原地迁移：正文字节和卡片位置不变，迁移本身不自动提交。
- 右键侧栏中的文件夹，选择“在文件管理器中打开”，在运行服务的电脑上打开所选文件夹，不切换当前画布；顶部不设独立按钮。在远程 orb 中不会打开你电脑上的文件夹。
- 文章位置和文档区按文件夹保存在 `canvas/<文件夹>/_canvas.json`（随同步提交），不会改动 `.md` 正文或文件修改时间。
- **同步**：正文实时自动保存；侧栏「同步」一次完成：读取本机改动 → 按章节分级（措辞 / 新增 / 关键表述）→ 总结模型增量更新记忆 → 撰写提交说明 → 提交 → 拉取并合并远端更新 → 上传本机提交（设置中填写远端，使用本机 Git 已有的登录方式）。即使本机没有新改动，也会检查并接收远端更新。未配置远端时只在本机提交；措辞改动不调用模型。记忆和布局冲突以本机为准，笔记正文冲突时保留本地提交并提示手动处理，不强制覆盖远端。
- 可使用其他编辑器修改正文，网页会同步标题、摘要和正文，位置不会改变。
- 远程 orb 预览使用独立的示例笔记，不能读取你自己电脑的文件。

## 开发分支：数据备份与恢复

**先停止笔记服务并暂停其他编辑器的写入。** 在 `web/` 下执行，两个目标目录都必须尚不存在、父目录必须存在，且不能放在源目录里面：

```sh
node --import tsx server/backup-cli.ts backup /路径/数据仓库 /路径/新备份
node --import tsx server/backup-cli.ts restore /路径/新备份 /路径/新恢复目录
```

备份包含当前 Markdown、目录内附件、空文件夹、记忆、布局、身份和本地历史，并逐文件校验字节与 SHA-256。v1 仓库备份额外保留旧缓存中的会话、提案和撤销记录；备份本身不升级源数据。不复制 `.git/`、可重建缓存或配置目录中的连接凭据，也不会下载外部图片链接。恢复后需要重新配置模型连接及 Git；这不是 Git 提交历史的备份。

服务和备份命令共用占用锁，同一目录不能被两个本版服务同时打开。异常退出后可能需等一分钟再试；不要删除锁文件强行启动。它是本地进程之间的约定，不能阻止旧版本或其他编辑器写文件，也不适用于网络盘上的多机并发。

Agent 批量修改前保存恢复记录；若进程中断，下次启动先恢复未完成的批次，再显示笔记。确认和撤销的重复请求不再重复修改文件。若文件、布局或身份出现无法判断的新改动，停止写入并保留记录，不强制覆盖；此时保留整个目录，再从可信备份恢复到新目录检查。没有画布快照的旧布局提案必须重新生成。应用内移动保留身份；外部改名不会猜测它与旧文章的关系。

当前已验证的是 Linux 本地文件系统上的进程中断和故障恢复，不承诺断电、磁盘损坏、恶意并发写入或任意文件系统上的事务保证。助手运行中暂不允许同步，避免同步提炼记忆与回答保存互相覆盖；同步期间其他笔记写入会等待。Note/Chat 统一界面、分支讨论和新草稿协议尚未接入。

## Amp 开发环境

仓库根目录的 `.agents/setup` 使用 orb 预装的 Node.js/npm，按锁文件安装全部开发依赖；不启动服务、不清空笔记、不保存登录凭据。当前已验证 Node 26.10.0；安装会检查依赖所需的 Node 版本，不兼容时明确失败。

预览服务在 `.amp/services.yaml` 中声明。新 orb 打开 Portal 时，Amp 会启动缺少的服务；也可从仓库根目录执行：

```sh
./.agents/setup             # 手动重新准备依赖；新 orb 通常自动执行
amp orb services ensure    # 启动/检查预览，并输出当前环境的预览链接
```

API 固定使用本机端口 3001，网页使用 5173 并代理 API；健康检查验证网页到 API 的完整读取路径。服务由 Amp 管理，重复 ensure 不会启动副本；无需额外的 `.agents/resume` 重启脚本。

示例笔记位于根目录 `.amp/preview-notes`，连接设置位于 `.amp/preview-config`；重新准备和启动不重置已有数据。数据、凭据和自动生成的 portal 文件不提交到 Git；只提交服务定义，链接由 Amp 为当前环境生成。

配置需要进入项目默认分支后才会用于之后的新 orb；只有本地提交并不代表已经启用，也可改用 Amp 项目的启动前配置。当前连续运行 setup 两次约 16 秒/15 秒，重复 ensure 返回两个服务 HTTP 200，111 项测试、类型检查及构建通过；现有依赖配套版本警告和构建体积提示仍保留，未在环境配置中强制升级或屏蔽。

## 安全说明

服务可以读写本机文件且没有登录，所以只监听 `127.0.0.1`，只接受发往 localhost 的请求，
并且写操作只接受 JSON。不要把它直接暴露到公网。

## 当前功能

- **多文章画布**：默认显示标题、正文的纯文本摘要和文件名。拖动卡片自由摆放，选中后方向键每次移动 20 个画布单位；平移、缩放、查看全部只改变视角，不排列文章。
- **文档区**：右键文章，在菜单中选择“创建文档区”；按住 Shift 再右键其他文章可以多选后一起创建，只包含明确选中的文章。其他文章拖到区域正文范围内、卡片中心进入后自动加入；区域随成员自动扩展或收缩，不挪动其他文章。拖出后脱离；拖动区域标题或聚焦后用方向键整组移动，经过其他文章不自动收纳。支持改名、拖动右下角调整大小，不能缩小到盖不住已有成员；“解散文档区”保留文章、正文和所有当前位置。区域不嵌套，同一文件夹内一篇文章最多属于一个文档区，不移动真实文件。
- **位置稳定**：修改标题、正文或文件修改时间，以及新增文章、重新打开、重启服务，都不会重新排列已有文章。只有新文件分配初始位置，放在已有文章下方；外部重命名或移动文件目前按新路径视为新文章。
- **打开与预览**：单击选中，空格只读预览，双击或 Enter 打开编辑器；文章右键菜单也提供“预览文章”和“打开并编辑”。Esc 关闭预览并恢复焦点。
- **单篇编辑**：默认使用成熟开源的 [Milkdown Crepe](https://github.com/Milkdown/milkdown)（MIT，基于 ProseMirror）。直接在排版后的正文里修改标题、粗体、引用、列表、待办、表格和代码块，不设格式工具栏、斜杠菜单、分栏或阅读切换。输入 `# `、`## ` 创建标题，`**文字**` 转为粗体。正文行宽最多 720px，文字左对齐，左右留白自适应；滚动区域铺满可用工作区，不在正文旁放置窄滚动框。保存状态、手动保存和撤销在底栏。编辑器、字体和样式由本地服务提供，不依赖在线编辑器或 CDN。
- **源码与保真**：保留 `@uiw/react-md-editor` 作为无工具栏的源码入口。打开文章或仅切换编辑方式不会改写文件；实际富文本修改会重新生成 Markdown，可能统一列表符号、空行和表格空格，额外空段落采用 `<br />`。需要逐字符保留写法时请使用源码。YAML/TOML frontmatter、引用式链接、脚注、原始 HTML（独立空行标记除外）及代码块元数据自动使用源码，避免静默丢失结构。暂不提供图片粘贴/拖入上传或数学公式渲染。
- **长文定位**：两种编辑方式均保留跟随草稿更新的六级目录，点击定位对应标题。目录默认收起，通过顶部“目录”展开右侧面板；关闭按钮和 Esc 均能真正关闭，并把焦点返回入口。正文在剩余空间居中。源码切回时恢复原有光标、选区方向和滚动位置；写作视图重新打开时从正文开头开始。切换方式会清除 AI 选区，避免两种编辑器的位置混用。正文链接使用 Ctrl/⌘ 点击，或悬停后点击链接地址打开；相对 `.md` 链接在应用内跳转。
- **新建与引用**：新建真实文件夹、选择文章所在文件夹、快速输入正文、引用已有文章。引用是可迁移的相对 Markdown 链接，支持安全的同目录、子目录、父目录跳转。
- **搜索**：搜索标题、正文、文件夹；方向键/Enter 选择，Esc 关闭。⌘/Ctrl K 打开搜索（编辑器内该组合键由编辑器处理）；⌘/Ctrl N 新建，⌘/Ctrl S 保存。
- **保存保护**：自动保存、离开前等待最新草稿保存、原子写入、写前内容核对。外部编辑冲突时保留草稿，不用旧正文覆盖新文件。编辑器保存与 Agent 修改分别可撤销；接受外部新正文后清除旧保存撤销历史。位置保存失败保留待保存位置并提供重试，阻止离开丢失修改。
- **外观**：浅色、深色、跟随系统。左侧导航可折叠为工具窄栏，仍保留展开、搜索、新建、返回画布和设置入口；浏览器记住折叠状态。
- **AI Agent**：文件夹画布和文章页共用 Arc `ai-chat` 助手。对话范围（当前文章 / 文件夹 / 纯聊天）是"焦点"：决定首先关注什么、带入哪些记忆，工具可以查阅整个笔记库；纯聊天不提供任何笔记工具。工具包括目录、全文/正则搜索、语义搜索、按章节读取、读记忆、Git 历史与改动比较、链接与反向链接、读画布；编辑、按章节编辑、重写、新建、批量替换、重命名与批量重命名（自动改写所有链接，记忆和画布位置跟随）、移动、重命名文件夹、删除、拆分；移动卡片、建立/调整/解散文档区、按主题整理画布、在画布上定位；记住与修订记忆；提案、计划和并行分析。回复流式显示；对话保存在本机，刷新和重启后可继续，过长时自动压缩。
- **改动集与提案**：一次请求中助手的全部修改（正文、记忆、画布）是一个改动集，可以查看差异并整组撤销；之后若有文件被再次修改，撤销会被拒绝，不覆盖新内容。你明确要求的修改直接执行；助手自己认为应该做的修改只能作为提案，在面板中确认后才执行，执行前重新核对内容。
- **记忆**：每篇文章、每个文件夹和整个笔记库各有一份记忆，服务于以后使用这些笔记（写新文章、回顾学习、准备讨论、检索事实），不是修改日记。文章页「记忆」、画布「文件夹记忆」可以查看和编辑。
- **助手分栏**：使用 Arc `resizable-panels` 拖动画布/文章与助手之间的分界，聚焦分界后也可用方向键调整，Shift 加方向键大步调整、双击恢复初始比例。浏览器记住分栏宽度，关闭或调整面板不重建编辑器、不丢草稿与选区。窄于 820px 的窗口使用覆盖式面板。Enter 发送，Shift+Enter 换行，中文输入法组词时不发送；快捷要求只填入输入框，不自动发送。

## AI 连接与边界

### ChatGPT 官方登录

设置中的 **Continue with ChatGPT** 使用 OpenAI 官方开源工具登录流程，支持符合条件的 ChatGPT 方案使用，不需要粘贴 API 密钥。
保存每个账号/工作区注册、读取可用模型、选择模型、刷新会话、重新登录、退出并尝试撤销授权。
只调用官方公共 Models / Responses 接口，不使用非官方 ChatGPT 后端接口，不读取聊天记录。

**必须在运行笔记服务的同一台电脑上打开浏览器完成登录。** 官方回调使用临时 `127.0.0.1` 端口；远程 portal 预览禁用登录，并说明原因。
实际可用性受账号方案、工作区政策、地区和额度限制。额度可在 https://chatgpt.com/settings/usage 查看。
登录失效、额度不足或配置损坏时，不会自动改用 API 密钥产生另一种费用；切换需手动选择。

本轮用模拟官方服务、真实本机 HTTP 回调和签名校验测试授权、刷新、退出和流式结果；**尚未使用真实 ChatGPT 账号完成授权和模型调用验收**。

### 其他模型服务

也可填写 OpenAI 兼容地址、模型名称和 API 密钥，测试后保存，无需重启。讨论和编辑笔记需要模型支持工具调用（function calling）；不支持的模型只能纯聊天。
切换服务地址必须重新填写密钥，不会把旧密钥发给新地址。测试只发送简短测试消息，不读取笔记，不自动保存设置。

连接按工作区路径分开保存在本机配置目录，位于笔记文件夹之外：macOS 使用
`~/Library/Application Support/Sidemind/connections`，Windows 使用 `%APPDATA%/Sidemind/connections`，
Linux 使用 `$XDG_CONFIG_HOME/sidemind/connections`（默认 `~/.config/sidemind/connections`）。
首次启动时，如果旧的 Canvas Note 连接目录（`CanvasNote`、`canvas-note`）存在，会把其中的文件复制过来，旧目录不会被改动或删除；
显式指定配置目录时不做复制。可用 `SIDEMIND_CONFIG_DIR`（旧名称 `CANVAS_CONFIG_DIR`）指定独立配置目录。目录和文件在支持 POSIX 权限的平台分别使用 0700、0600；
密钥是本机的私有配置，不是系统钥匙串加密存储。已保存的密钥不会返回网页或写入浏览器存储。
移除连接会清除该文件里的密钥，并保留断开状态，避免重启后回退到旧环境变量中的密钥。

仍兼容启动时提供 `SIDEMIND_AI_API_KEY`、`SIDEMIND_AI_MODEL` 和可选的
`SIDEMIND_AI_BASE_URL`（旧名称 `CANVAS_AI_API_KEY`、`CANVAS_AI_KEY`、`CANVAS_AI_MODEL`、`CANVAS_AI_BASE_URL` 仍可用）。界面保存的设置优先；远程地址需要 HTTPS，本机服务可使用 HTTP。
### 三个模型槽位

设置「API 与模型」中分别配置：**主对话**（ChatGPT 或 OpenAI 兼容 API）、**总结与校验模型**（推送时更新记忆和写提交说明、压缩长对话、并行分析，建议用便宜模型；未配置时使用主对话模型）、**Embedding 服务**（OpenAI 兼容 `/embeddings`，用于语义搜索和相关文章；未配置时不影响其他功能，向量按内容哈希缓存在 `cache/embeddings.json`，换模型自动重建）。三者的密钥都保存在笔记仓库之外的本机配置目录。

### 写入纪律

编辑前必须读取并使用当前版本；整篇重写和拆分要求读完全文；精确替换保留未涉及的文字和换行。写入工具先校验全部操作并保存恢复记录，中途失败尝试还原；若发现无法安全还原的新改动则停止写入，不覆盖外部内容。这不是跨文件系统事务。发送文件任务前会先保存当前草稿。助手不能提交或推送。生成和连接测试均可停止；停止时已完成的修改保留在改动集中，可以整组撤销。未配置时展示连接入口，不生成模拟结果；被截断的模型回复不会执行工具。

## 旧版本数据

旧的单篇文章块布局与“空间”分类不再作为当前画布组织方式；旧 `.board.json` 文件保留不删，不自动移动正文文件。
已有 Markdown 保持原样，新布局按真实文件路径保存。旧版最近访问时间在首次分配文章位置时尽可能保留。
新布局文件损坏时停止布局写入，避免覆盖原位置；Markdown 文件仍可由其他编辑器或单篇读取接口打开。

### 首屏资源优化

画布先加载，编辑器代码和样式在画布就绪后的浏览器空闲时预加载；首次立即打开也会等待同一份编辑器资源，不绕过离开前保存保护。使用 uiw 官方 `nohighlight` 入口：普通编辑或没有代码块的预览不下载语言规则，含代码块的分栏预览再按需加载完整语言支持。保留安全 HTML、表格、格式命令、链接及目录定位；加载失败提示不会遮住正文或保存入口，未着色代码仍可读写。

生产服务对 `/assets/*` 启用协商压缩，笔记接口与实时事件流不压缩；现有开发预览仍使用 Vite，不用于下面的生产性能对比。

本轮优化前后生产构建使用同一 Chromium、2340×1254、2× 像素密度、十篇隔离文章，每轮清缓存，模拟 180ms 网络延迟、10Mbps 下载和 CPU 4× 减速，前后交替各测五次。耗时取中位数，资源量是浏览器记录的 JavaScript + CSS 实际传输字节，含请求开销。

| 项目 | 优化前 | 优化后 |
| --- | --- | --- |
| 首次导航到画布可用 | 3247.7ms | 1067.7ms |
| 画布可用时已传输资源 | 1,948,515 字节 | 280,090 字节 |
| 包括编辑器空闲预加载的资源 | 1,948,515 字节 | 382,234 字节 |
| 双击到正文可编辑（等候 1.2 秒供空闲预加载） | 272.1ms | 272.8ms |

收益来自推迟不需要的工作与实际压缩，不是总功能代码减少 85%。主 JavaScript 从 1742.69kB 拆为约 803.87kB；编辑器约 294.46kB，完整语言规则约 601.65kB，后两者分别延后加载。构建对超过 500kB 的资源仍提示，未屏蔽；全部资源总量没有明显缩小。以上不是用户设备实测，也不是上千文章或超长正文的压力测试。

## 开发分支：导入 ChatGit 的画布

只导入 ChatGit 当前的画布数据（`chatgit_canvases` / `chatgit_nodes`）。**不读取也不迁移 API Key、登录令牌、数据库凭据和源用户 ID；不会调用任何模型。**先在装有 ChatGit 数据的机器上用 MongoDB 自带工具导出这两个集合（得到 `chatgit_canvases.json` 与 `chatgit_nodes.json`），拷贝到一个目录：

```sh
mongoexport --db ChatGit --collection chatgit_canvases --jsonArray --out chatgit_canvases.json
mongoexport --db ChatGit --collection chatgit_nodes    --jsonArray --out chatgit_nodes.json
```

之后在 `web/` 下按下面顺序做（**导入、核对、回退需要先停止笔记服务**）。建议先导入到一个**新的**目标目录试用，不要直接写进正在使用的数据目录：

```sh
node --import tsx server/import-cli.ts preflight <导出目录>                 # 只读预检，什么都不写
node --import tsx server/import-cli.ts import    <导出目录> <数据目录>       # 目标不存在则新建；已有数据时必须加 --backup <新备份目录>
node --import tsx server/import-cli.ts verify    <导出目录> <数据目录>       # 逐节点核对数量、边、文字校验值、草稿、未完成回答
node --import tsx server/import-cli.ts rollback  <批次编号> <数据目录> --backup <新备份目录>
```

- 一个画布变成一个讨论，一个节点变成一个问题（完成的带一条回答，原摘要进入摘要库）；划词提问把原文引用写进问题文字；草稿按画布保留。时间保持源系统的时间。
- 编号由源编号派生，所以**重复导入同一份导出不会产生第二份**，中断后重新运行会接着补缺失的部分；导入后被你改动过的讨论会报告为“冲突”，不会被覆盖。
- 源系统里生成中、出错、被停止的节点导入为**未完成的回答**（保留已有文字，可点“重试”），不会自动调用模型。
- 不能迁入的内容会逐项报告而不是悄悄丢掉：附件（只保留名称）、“可能的下一个问题”建议、端点/模型选择、界面状态。成环的画布、属于不存在画布的孤立节点会被跳过并说明原因；指向不存在父节点的边会被丢弃，节点作为起点导入。
- 回退会先完整备份，再把这批导入的讨论、草稿、运行记录和摘要**移入 `local/imports/<批次>-archive/`（不删除）**；导入后新增的内容随归档保留。如果已有笔记引用了导入的回答，回退会被拒绝。回退后同一份导出不能再导入。
- 导入后两个应用的数据互不同步；这个工具只把数据复制过来，不会回写 ChatGit。
