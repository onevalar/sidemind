# ChatGit 画布研究对话：设计决定

记录 2026-10-11 至 10-12 讨论与原型比较后确定的交互和架构。原型（`.amp/in/explore-canvas/`，未提交）比较了"输入框托盘""原文批注""画布草稿"三种攒问题方式，最终采用"组合"方案并支持多个草稿。

## 产品定位

研究、学习型对话：一个回答里有多个不懂的概念，用户分别追问，各条思路的脉络在画布上一目了然。普通日常问答不是主要场景。

## 核心概念

- **节点 = 一轮问答**（问题 + 回答），不再把问题和回答拆成两张卡片。
- **上下文规则由系统决定，用户不勾选"用作上下文"**：
  - 延续：接在某个节点后提问，继承从起点到它的整条路径。
  - 划词分支：继承路径，并附带被选中的原文片段。
  - 合并提问：一个新节点有多个来源，共同祖先只发送一次。
- 分支之间默认互不影响；只有用户合并或引用时才共享内容。
- 长路径自动压缩：最近几轮保留原文，更早的用摘要代替；被引用的原文片段与合并来源不压缩。用户可展开查看"下一问会带上什么"。
- 不自动替用户展开分支；回答末尾可以有推荐提问，点击才发送。

## 交互

- **划词提问**：选中回答里的文字，弹出小输入框。
  - Enter：立即发送，生成一个新分支，用户留在当前阅读位置继续划词（并行）。
  - Ctrl/⌘ + Enter：加入当前草稿；Ctrl/⌘ + Shift + Enter：加入新草稿；分割按钮下拉可选其他草稿。
  - 留空发送 = 请 AI 解释这段。
  - 已问过的片段在原文中虚线下划线，点击跳到对应分支。
- **草稿分支（组合方案）**：同一个草稿同时出现在三处，各司其职。
  - 输入框：唯一的编辑与发送入口，每条一行（编号、原文片段、可改的问题），可补一个总问题；多个草稿用标签切换、可改名。
  - 原文：带草稿字母的编号高亮（A1、B2），当前草稿蓝色、其他灰色；点编号定位到输入框里对应条目。
  - 画布：每个草稿一个虚线节点，接在来源下面；可单独发送、清空、设为当前。
  - 草稿条目来自不在同一路径上的节点时，发送后成为合并提问。
- **节点操作**：左键选中并在侧栏阅读；右键菜单（从这里提问、在对话中阅读、选中以合并）；Shift + 点击多选后"基于它们提问"。
- **一次问多个**：输入框里攒多条问题，同时生成多个并行分支；一个问题时跟过去，多个时留在原地并提示。
- **输入框始终说明这一问接在哪里**：继续追问 / 新建分支（已有 N 个后续）/ 合并提问 / 新的起点。

## 界面

- 画布从上到下展开（竖向占用，横向留给侧栏）。
- 三种视图：只看画布、画布 + 对话（侧栏）、只看对话；同一份数据。
- 侧栏是单一分支的线性阅读：从起点到当前节点，面包屑、分叉提示（此处还有 N 个分支）、当前路径在画布上高亮。
- 侧边导航以"画布 = 一个研究主题"为单位。
- 全部使用 Arc UI 组件（私有 `onevalar/arc-ui` 的 `custom/arc/`，含 Pro）；Arc 没有的画布层用 Arc 设计变量自绘。Arc 按钮文字不截断，长标题列表行用原生按钮 + Arc 变量。

## 架构

- 自有图数据模型（画布、节点、边、草稿、路径摘要缓存），不再借用 LibreChat 的 `parentMessageId` 消息树。
- 上下文编排在服务端：收集来源 → 去重 → 按预算压缩 → 组装消息 → 调用模型。
- LibreChat 只提供基础能力：模型连接与流式生成、认证与本机模式、附件、语音、存储。
- Arc 面向 React 19，LibreChat 客户端是 React 18，因此新界面是独立前端，由同一个 Express 服务提供。

## 许可

Arc Pro 源码只能用于私有项目：`chat-git` 必须保持私有，不得发布包含 Arc 源码的包或模板。
